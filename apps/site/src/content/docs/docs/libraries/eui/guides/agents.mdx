## The catalog prompt

`catalogPrompt()` writes the system prompt that teaches a model the catalog: every component, prop and enum in one sentence each, the style whitelist and the token names. It is budgeted and gated in CI:

| Variant | Components | Size (tokens, estimated) |
|---|---|---|
| `catalogPrompt()` | {promptBudget.full.components} | {tokens(promptBudget.full.tokens)} |
| `{ lite: true }` | {promptBudget.lite.components} | {tokens(promptBudget.lite.tokens)} |
| `{ terse: true }` | {promptBudget.terse.components} | {tokens(promptBudget.terse.tokens)} |
| `{ sections: ["rules", "index", "functions", "style"] }` | {promptBudget.index.components} (one line each) | {tokens(promptBudget.index.tokens)} |
| `{ sections: ["rules"] }` | – | {tokens(promptBudget.rules.tokens)} |
| `componentPrompt(name)` | 1 | {tokens(promptBudget.perComponent.meanTokens)} on average |

The prompt is sectioned: `sections` picks what to print, `only` narrows the component blocks to the ones a task needs, and `componentPrompt(name)` is one component's block on demand. A host serves the rules and the index first and answers a model's request for a component with its block, which is how the [ergonomics eval](/docs/libraries/eui/reference/eval/) measured the cheapest prompt. Pass `extensions` to include yours. The [playground](/docs/libraries/eui/tools/playground/) shows every variant in full.

## A2UI over MCP

This MCP server has one tool whose description is the catalog prompt. A valid answer goes back as A2UI over MCP: a resource with the mime type `application/json+a2ui` holding the JSONL messages. The user's actions come back as a `tools/call` of `a2ui_event`.

<GuideFile path="agent/server.ts" />

On the client, `McpTransport` unpacks those resources into surfaces and sends actions back as tool calls, so any host from the render guides can show what this agent draws.

## Validate

Treat a model's JSON as untrusted. `reduceSurface(components, { catalogId })` always returns: the tree and a list of issues (an unknown component, a bad prop, a missing child). Send the issues back as a tool error and the model retries. For structured outputs or a validator of your own, `coreSchema()` is the whole catalog as JSON Schema, with the core catalog id <code>{componentsDoc.catalogId}</code>.

A `Motion` carries a whole animation: `motionPropsProblems(props)` from `@exponential_app/eui/motion/server` checks it with the animation engine itself (the dialect compiles, Lottie has no expressions, the limits hold) and names every problem with its JSON pointer. See [Animate with Motion](/docs/libraries/motion/guides/animate/).

## Compiled in CI

`bun packages/exponential-ui/guides/check.ts agent` builds [guides/agent](https://github.com/Niach/exponential/blob/master/packages/exponential-ui/guides/agent), starts the server and asks it for a valid and an invalid surface over MCP.
