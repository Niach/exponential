## The setup

[The corpus](https://github.com/Niach/exponential/blob/master/packages/exponential-ui/eval/corpus.json) is what a product person types: a settings page, an issue list with filters, a device dashboard, a form with validation, a chat, a kanban, a data table, a wizard, an empty state, a phone inbox at four widths.

- `record.ts` sends each prompt to Claude with `catalogPrompt()` as the system prompt and caches the reply as a fixture.
- `score.ts` validates every reply with the reducer the renderers use and scores it.
- `render.ts` paints it in the React renderer, the Solid renderer and the `<exponential-surface>` element, measures each one's boxes and compares them with React.
- `parity.ts` measures the sample template against a reference layout on the stored shots.

```sh
bun run --filter @exponential_app/eui eval:record   # once, needs ANTHROPIC_API_KEY
bun run --filter @exponential_app/eui eval          # score the fixtures → eval/report.json
bun run --filter @exponential_app/eui eval:render   # web renders, React + Solid + element, at every width (Playwright)
bun run --filter @exponential_app/eui eval:parity   # the sample template vs a reference layout
```

## Rendered on the web

Every surface painted by the React renderer, the Solid renderer and the `<exponential-surface>` element in the exponential theme at its widths. The gaps are the measured distances between the root's children; the inset is where the first text starts. Solid and the element must measure the same boxes and paint the same pixels as React (the web-parity gate enforces it), so any difference is a finding.
