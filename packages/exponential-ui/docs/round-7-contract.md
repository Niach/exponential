### Structure

`list` (row, full width, centred; strip recipe: no fill, gap xs) → per tab,
in strip order, an `item` (row, centred, no shrink, max `tabStripMaxWidth`;
recipe: `buttonSm` tall (exponential: `buttonMd` = 32, the IDE chip), radius
sm, hairline `border`, padding-x xxs; `selected` = `accent` fill + `input`
border) holding the `tab` (icon + title, shrinks, truncates; recipe: `chip`
tall, padding-x sm, regular weight, transparent at every state, muted →
foreground on hover/selected) and its `close` (the EXP-1259 glyph, 24 × 24
round in the strip, `closable: hover` = only while its tab or itself is
hovered or focused) → `more` (the `+N` button: the chip box at rest,
padding-x sm, tabular figures) → `new` (24 × 24 round). No indicator.

Spacing = the IDE work tab's (`surface::strip_chip_frame`, web
`StripChip`): the title starts 10 in (item xxs + tab sm), icon → title
`$spacing.xs` (4; the IDE's chip gap moved 6 → 4 to match, desktop and
web), and with a close the tab's inline-end padding and the item's are
`$spacing.xs`, so title → × = 4 and × → border = 4 (the core sets them as
per-side layout styles, which win over the recipe's padding-x; the web
base CSS restates them).

### Fit

After every layout the renderer measures each item (folded ones TOO: they
stay laid out out of flow, `position: absolute` + `visibility: hidden` +
`pointer-events: none`, so their widths keep feeding the fit), the `+N`
button and the `+`, and runs `partitionTabs(widths, list width − (+ width +
gap), gap, +N width, active slot)`: tabs pack in strip order until the next
does not fit, the `+N` width is reserved only once something overflows, the
active tab always shows, one tab always survives. The `+N` shows the folded
count; a press fires `more {values}` (the folded tabs' values in array
order; the host opens its own menu). The Rust core refits after each pass
(`Surface::fit_tab_strips`, at most two extra rounds a pass, never during a
drag); the web renderers refit on every render and on a resize.

### Reorder

The host owns `tabs`: a move fires `reorder {from, to, value}` (array
indexes; `to` = the array position of the tab whose slot the dragged one
took) and nothing is written. A drag: a pointer (mouse/pen) press that
travels `tabDragThreshold`, a touch that rests `tabLongPressMs` (moving
first = a scroll or a press). Painters send the core `drag {phase:
start|move|end, delta}` on the `tab` (delta = px since the start, screen
direction, like a Resizable handle); the core snapshots the visible item
centres at the start, `tabDropSlot` = how many other centres the dragged
centre passed in reading order (rtl mirrored), previews the order
(`local.tab_order`) while it moves and fires on the end (none when the tab
ends where it started). The release after a drag is no press. Keyboard:
Ctrl/Cmd+Shift+ArrowLeft/ArrowRight on a focused strip tab → `key {key}`:
one place in screen direction, nothing past an end.

### Per-renderer checklist

- **Rust core / FFI**: strip build (`layout_tree/containers.rs`), fit +
  drag + key (`surface/tabs.rs`), pure rules (`tabs_strip.rs`); no new FFI
  API (events go through `event`).
- **React / Solid / element**: the strip DOM (items wrapping the Radix
  trigger + close, `data-folded`, the `+N` button), the shared controller
  `@exponential_app/eui/web` `tabs-strip.ts` (`stripFit`, `startStripDrag`,
  `stripKeyMove`, `isReorderKey`), base CSS; Solid is DOM-parity-gated
  (`nav.parity.test.tsx`), both replay `tabsReorder`.
- **gpui**: a strip tab's press becomes a drag past `tabDragThreshold`
  (the press is spent), Ctrl/Cmd+Shift+Arrow → `key`
  (`tests/interaction.rs`).
- **SwiftUI / Compose**: a long-press drag on a strip tab feeds `drag`
  (`TabStripDragModifier`, `tabStripDrag`); the rest is the core's frames.
  No hardware-keyboard chord on the phones yet.

### Placement

### `anchor`: open against any node

`anchor` names a node id anywhere in the surface. The overlay then opens
against THAT node's frame instead of its own trigger, and that node becomes
its TRIGGER, on every renderer:

- a press on it toggles the overlay (`open` writes through when bound; a
  Menu, which has no `open` prop, toggles its local state);
- it carries the trigger's semantics (web: `aria-haspopup` dialog | menu,
  `aria-expanded`, `aria-controls` = the content's id while open,
  `data-state`; natives: the node's `triggerFor` = the overlay's id);
- a press on it is never an "outside" press of a non-modal overlay (the
  press closes it as a toggle instead of dismissing and reopening);
- Escape (a `dismiss` on the layer root) closes the overlay and returns focus
  to the anchor (the natives' focus return reads `trigger(of:)` / the layer
  return, which the anchor now is).

The overlay itself lays out nothing (`data-xui-overlay-root="none"` on web,
the zero-size wrapper in the core). A Menu with an `anchor` and no child
draws NO default trigger; with a child, the child toggles it too. An id that
names no painted node leaves the overlay against its own wrapper. Only the
FIRST node with that id that is not already a trigger is linked.

An open anchored overlay (Popover, Menu, Tooltip, a picker's popup) CLOSES,
as Escape would (`open: false` + `change`), once its anchor is lost (#EXP-1739,
`fixtures/interactions-round1.json` `overlayAnchor`): a scroll container
holding the anchor scrolls, the anchor's box moves, or the anchor leaves the
tree (an overlay that fell back to its wrapper counts as moved). Core:
`Surface::close_overlays_in` on a scroll, `check_anchor_frames` on a finished
pass (the close lands at the start of the next one and is raised through
`take_events`, which every native host drains). Web: `watchAnchor`
(`@exponential_app/eui/web`), one per open overlay in React and Solid; while
the document's web fonts load it re-measures the anchor instead (a font swap
re-lays the page out, it moves nothing: the core lays out with its fonts
loaded), and the frame after they settle is the box it opened at.

Core: `Builder::link_anchors` runs after the whole tree is built (so the
anchor may come after the overlay in tree order): it sets the node's
`trigger_for`, makes it pressable (not for `openOn: hover`), and points the
open layer's `Anchored { anchor }` at it. A subtree rebuild over an anchored
node rebuilds fully (`Surface::anchor_ids`).

### The rule

With `hosted_popups` on, every layer of a Popover or a Menu (its submenus
too) placed against an anchor or a point is HOSTED:

- it lays out at its natural size, NOT clamped to the surface's width;
- it sits against its anchor by `anchor_position`: the side and the
  (physical) alignment, `OVERLAY_OFFSET` away, NO flip and NO shift, so
  its frames (surface coordinates) may lie outside the surface (a top-start
  menu over a 44 px panel has a negative y);
- `Layer.hosted` = true, `Layer.anchor_frame` = the anchor's frame,
  `placement.side` + `align` = the placement, the root frame = the
  popup's unclipped size: what an `xdg_positioner` takes (anchor rect,
  anchor edge + gravity from side/align, size; constraint adjustment =
  flip + slide, the compositor's);
- events are unchanged: they target node indices, so a host forwards a
  press at popup coordinates + the root's origin, and `dismiss` on the
  layer root closes it (the compositor's `popup_done`).

Dialogs, Drawers, Tooltips, toasts and the picker popups (Select, DatePicker)
are never hosted.

### Per SDK

- **web (React, Solid; element through Solid)**: `host.popupHost.mount`
  is asked when the popup opens (again when its anchor's element resolves)
  with `{owner, kind, anchor (the anchor's box in surface coordinates),
  side, align (physical)}`; the returned element receives the content
  through the renderer's portal (presses, Escape, outside presses and focus
  return still route through the surface's tree) and takes the surface's
  theme scope (`xui-surface` classes, `data-xui-mode`, `dir`);
  the popper wrapper lays out in flow inside it, the HOST positions it
  (e.g. at `anchorPosition`). `null` keeps the in-surface overlay;
  `unmount` hears it close. Web needs no core setting (its renderers place
  overlays themselves).
- **gpui**: turn on `SurfaceSettings::hosted_popups`; the view paints no
  hosted layer, `HostPlugin::on_hosted_popups` hears the set whenever it
  changes; the host renders `hosted_popup_element(owner)` (the layer at
  (0, 0), any window: its listeners update the surface's view) and calls
  `dismiss_hosted_popup`. A press in the surface's window never counts as
  inside a hosted popup.
- **SwiftUI / Compose**: turn on `hostedPopups` and provide the host
  (`.exponentialPopupHost` / `LocalPopupHost`): it receives
  `HostedPopup`s with the layer's geometry and a `content` view /
  composable wired to the model; the surface paints none of them (without a
  host they paint as the default popups).
