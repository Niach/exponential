# The ergonomics eval (VAPP-108)

How well an agent builds app screens from `catalogPrompt()`, measured: a
corpus of app-building prompts, the model's replies cached as fixtures, every
reply validated, rendered and scored. CI replays the fixtures and never calls
a model.

| file | what |
|---|---|
| `corpus.json` | the prompts: id, the prompt text, the web widths it renders at, the app screen it mirrors (`views.json` id), what the rubric expects of it |
| `fixtures/<id>.json` | one recorded reply per prompt: the model, the prompt variant, the usage, `recordedBy` (`api` = record.ts over the Anthropic API with a key; `claude-cli` = record.ts through `claude -p` on the machine's Claude login, real usage incl. ≈ 0.5k tokens of CLI context, VAPP-127; `session` = the session's own model from the same prompt, usage estimated), and the reply `text` verbatim |
| `lib.ts` | the pure half: the reply parser (JSONL, a fenced block, an array, prose around them), the surface, the validator pass, the rubric, the spacing stats, the aggregate |
| `record.ts` | `bun run eval:record [--only id] [--force] [--model] [--variant] [--effort] [--via sdk\|claude-cli]`: records the corpus (Anthropic SDK, `claude-opus-5-5` by default, streaming, the system prompt cached, `fallbacks: "default"`; credentials from the environment), or with `--via claude-cli` through `claude -p` (the same system prompt replacing the CLI's, no tools, from an empty dir) on a machine with no key |
| `eval-specimens.json` | GENERATED by score.ts (VAPP-127): every fixture as a native specimen, the nested tree + data model render.ts hands the web, keyed `exponential-ui-eval-<id>`; the Compose example (`--es shot`), the Swift example (`-shot`) and the IDE (`EXP_DEV_SCREEN`) paint one by id |
| `score.ts` | `bun run eval`: scores every fixture → `report.json` (the numbers the issue, the site's `/eval/` page and `eval.test.ts` read) |
| `render.ts` | `bun run eval:render`: paints every surface in EVERY web harness, React, Solid and the `<exponential-surface>` element (Playwright, still pictures as the web-parity gate takes them) at each width → `out/<id>/{react,solid,element}-<w>.png` (gitignored), the measured boxes of each into `report.json`, and each candidate's comparison with React: the boxes must agree and the pictures be pixel-identical; a difference is a finding (`differences`), which `eval.test.ts` keeps on record until the renderer is fixed |
| `natives.ts` | `bun run eval:natives` (VAPP-127): the frames the native hosts dumped during the shots pipeline's eval lane (`bun run shots -- --platform android,ios,desktop --views eval [--skip-seed]` → `out/<id>/<platform>.{webp,frames.json}`, gitignored) measured like the web and compared with the React render at the closest width → `report.json` `natives` |
| `parity.ts` | `bun run eval:parity`: the Devices template vs the native Devices page on the stored shots (web + desktop): band height, title inset, first row inset, the gap under the band, a pixel diff of the band → `report.json` |
| `rewrite-gaps.json` | every app screen classified expressible / macro / extension / native, with the candidate macros, and which gap classes also concern the Solid renderer (`renderers.solid`: extensions need a Solid twin, natives a Solid painter; macros are the reducer's; the element inherits Solid's); `gaps.test.ts` keeps it in lockstep with `views.json` |
| `report.json` | the eval on record (generated; `eval.test.ts` fails when the rows drift from the fixtures) |

Rerun order after a prompt or catalog change: `eval:record` (by hand, with a
key or `--via claude-cli`) → `eval` → `eval:render` → the shots pipeline's
`--views eval` lane per native → `eval:natives` → `eval:parity` (which also
compares every surface naming an `appView` with that app screen's stored
shot, `parity.surfaces`).
