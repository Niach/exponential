# Changelog: `@exponential_app/eui`

All notable changes to this package. The SDK packages share one version and
release together from a `eui-v<version>` tag (`packages/exponential-ui/release/README.md`).

## Unreleased

A row SPANS `by`..`until`; the month view's `month` gains `weeks` (Monday-first, padding days, lanes, "+N more" markers past `lanes`), `day` and the selected day's `agenda`; new `view=week` (`week`) and `view=timeline` (`timeline`: columns per week, month or quarter, month/year bands, rows grouped by `row`, `now`); `tone=<field>` colours each placed row `chart1`..`chart8`. ## 0.12.0 (2026-11-03)

- VAPP-218 (eApps U1): screens. A package's `screens: [{template, title, icon?, params?}]` (≤ 5, keyed by the template) is the navigation manifest the HOST paints (a sidebar on wide frames, the phone bottom bar on phones). The host function `app.navigate {screen, params?}` (a press or an action's `call` step; always allowed) opens one through `HostOptions.navigate` ×4 (TS, Rust core, Swift, Compose); its params land under `/params/*` and fill a binding source's `${params.<key>}` (percent-encoded). New `src/host/screens.ts` (Rust `host::screens`, FFI `resolve_screen_json`, `navigate_target_json`): `validatePackageScreens` (install refuses an unknown template, a duplicate, a sixth screen, a bad icon, a non-string param, a literal navigate target that is no screen), `resolveScreen`, `navigateTarget`, `fillScreenParams`; `catalog/host.json` `package.screens`; fixture `host-router.json` `screens` + `navigate`.
- VAPP-218: the style condition `@media (form-factor: phone|wide)`: the host's form factor (`formFactor` on the React/Solid surfaces, the web component, `SurfaceSettings` in Rust, Swift and Compose), unset = the surface width against `$breakpoint.md`; fixture `style-conditions.json`.

## 0.7.0 (2026-11-03)

- **Breaking** (hence the minor): eApps packages are `formatVersion: 3`, and a record kind may carry a per-kind `policy` (`read`/`create`/`update`/`delete`: `member | author | owners`); a version-2 package is migrated to 3 on the server, and hosts refuse newer formats.

- eApps dogfood fixes: an `expr` call's var whose binding resolves to nothing (a row's missing optional field) now reads `null` instead of failing as an unknown name and falling to the `default` (TS `resolveDynamic`, Rust `data::resolve_value`; `expressions.json` calls case). The gpui renderer defers a host function call out of the surface view's update: pressing a package action panicked (`cannot read SurfaceView while it is already being updated`); `SurfaceView::host_plugin` (a regression test drives the press path).
- **Breaking** eApps R3: per-kind record policies, `formatVersion` 3 (a version-2 package is `format version 2 is no longer read: write 3`). A kind may carry `policy: {read?, create?, update?, delete?}`, each `member | author | owners` (`create` never `author`; defaults `member/member/author/author`), validated at `/records/<kind>/policy`. New `src/host/record-policy.ts` (Rust `host::record_policy`): `recordPolicy(kind)`, `recordRefusal(policy, op, {id, role, access?}, row?)` (the member's app access `none | read | write` over the policy; the refusal texts `RECORD_POLICY_COPY`), `recordAllowed`, `readableRows`, `validateRecordPolicy`; fixture `fixtures/record-policy.json`. `applyRecordBatch` takes `role` (+ `access`): set, every write is judged by its kind's policy and a row the writer may not read is not found; a created row now carries `authorId` (Rust `apply_record_batch_as`). Package tests take `role` (`member | owner`, default member), read only the rows their member may read and write under the policy.
- eApps hardening: the CEL differential fuzz. `src/cel-fuzz.ts` generates seeded random expressions (well-typed, ill-typed, mutated, token soup, at the caps), var sets, type maps and A2UI calls; `fixtures/cel-fuzz.json` is its committed corpus (1200 cases + 240 calls, `bun run ./scripts/cel-fuzz.ts --write`), regenerated byte for byte by the TS test and replayed by the Rust core (`eui-core` tests/cel_fuzz.rs), so a disagreement between the twins fails CI. It found one bug in each twin, both fixed: `dateAdd` with a huge whole `n` wrote `0NaN-NaN-NaN` in TS and overflowed (a panic in debug, a wrapped date in release) in Rust; now every date and timestamp outside 0000-01-01..9999-12-31 and any `dateAdd` of more than 4 000 000 calendar steps is `date out of range`, checked before the calendar maths. `expressions.json` gains the cases.

- VAPP-160: `VoiceWave` hardening. `src/` reads `generated/style.runtime.json` (catalog/style.json without its `$comment`s, drift-gated), so no bundle ships the spec prose (about 15.4 KB less in the root, schema, conformance, host and web entries; the budgets lowered by exactly that). `voiceWaveClock(onFrame, el?)` takes the wave's element and ticks only while an IntersectionObserver sees it on screen (scrolled offscreen or in a `display: none` container: no frames). The catalog and a11y.json call the one child decorative (never a control). fixtures/voice-wave.json gains negative-level and negative-band cases (clamped to 0) for the rings and the bars. A test gates `VOICE_WAVE_SIZE_PX`, the size classes and every built-in theme's `VoiceWave/root` against each other. No visual change.

## 0.6.0 (2026-11-02)

- **Breaking** (hence the minor): eApps packages need `formatVersion: 2` and read records only through `records:<kind>`; an expression is pure (writes and host calls only in `actions`); every `{call: expr}` binding needs a `default`, and an unguarded optional (`T?`) value is an install issue.

- **Breaking** (eApps keeps no backwards compatibility): `formatVersion` is required and must be `PACKAGE_FORMAT_VERSION` (2): a missing one is `formatVersion is required (2)`, version 1 `format version 1 is no longer read: write 2`. `parseRecordsQuery(params, kind)` takes the kind only from its argument (no `kind` param; `kind` left `RECORDS_RESERVED_PARAMS` and filters a field like any other key); `expandQuerySource` keeps no `kind`; `validatePackage` and the expression checker follow only `records:` bindings. `harness.records.upsert/delete` left `WRITE_FUNCTIONS`. `authorId` joined `RECORD_RESERVED_KEYS`. `catalog/host.json` follows; fixtures use only the neutral spellings.

- **Breaking** VAPP-195 (E2): explicit missing values. The checker types a value that may be missing as `T?` (`{"?": T}`; `isOptional`, `optionalType`, `requiredType`, `typeDisplay` prints `T?`): a kind's field not in its schema's `required`, a var it cannot type (`dyn?`), an action's optional params, `data` and `me`. An unguarded use (arithmetic, ordering, `&& || !`, a condition, a macro's list, a function argument) is an install issue naming the path (`pathText`); guards: CEL's `has(a.b)`, `!= null` / `== null` (through `&&`, `||`, `!`, narrowing the branch), and the new pure function `orElse(x, default)` (catalog + bind table). Every `{call: "expr"}` in a package template needs a `default`; at bind time a failing or throwing call resolves to its `default` (absent = no value) on every renderer. Breaking for packages that read optional fields unguarded or whose expression bindings carry no `default`. Fixtures: `expressions.json` (optional check/eval/call/package cases), `actions.json` guarded.

- VAPP-196 (T1): package tests. New package key `tests: [{name, records?, now?, as?, expr | query | action, expect}]` (`src/host/tests.ts`, at most 50): `validatePackage` checks their shape and, on an otherwise valid package, runs each against its own in-memory store seeded with `records` at a fixed clock as the member `as`; a failing test is the issue `/tests/<i>` (`<name>: expected …, got …`). `runPackageTests`, `testMatches` (an object matches by the keys it names). `catalog/host.json` gains `package.tests`. Fixture `fixtures/package-tests.json`.

- VAPP-194 (E1): typed effects. `functionEffect(name)` = `pure | write | host` (`src/cel.ts`); CEL refuses a write or host function (`at 0: records.upsert writes: an expression is pure, use an action step`) and `validatePackage` refuses one in any pure place of a template (props, a call's args, an event's context; only an `on.*` `functionCall` may name one, and `actions.<name>` must name a declared action). New package key `actions: {<name>: {params?, steps}}` (`src/host/actions.ts`): steps `require`, `records.upsert`, `records.delete`, `set`, `call`, type-checked at install; `runAction(pkg, name, params, {data, me, now, offset, maxSteps})` → `{plan: {writes, sets, calls}} | {error}` over ONE snapshot (100 000 evaluation steps per run); `applyRecordBatch` + `RecordStore.batch` (all or nothing; `MemoryRecordStore`, `recordsHost`'s new `records.batch`). `ExponentialHost` runs `actions.<name>` calls: gate + consent for every host call first, ONE `records.batch`, the sets, then the calls; a failure is the new error code `ACTION_FAILED` + `HostOptions.onActionFailed`; new `HostOptions.me`, `now`, `zone`. `catalog/host.json` gains `package.actions`, `records.batch` and `ACTION_FAILED`. Fixture `fixtures/actions.json`.

- EXP-1624: the web primitives' ZoomableImage keeps the picture hidden until it loads (`imagePending`); `base-css` gains `.xui-zoom-placeholder` (the image glyph over the alt, on a muted tint) and draws a horizontal List's divider as a vertical hairline.
