All notable changes to this package. The SDK packages share one version and
release together from a `eui-v<version>` tag (`packages/exponential-ui/release/README.md`).

## Unreleased

## 0.3.0 (2026-10-31)

- VAPP-180: a package may EXPOSE MCP tools (`docs/package-format.md` "Exposes", `catalog/host.json` `package.exposes`): `exposes: [{name, title, description, input, access, run}]`, declarative bindings a host's MCP broker lists as `<app>__<name>` and runs as the calling person, `run` = exactly one of `records` (the package's own kinds: list, get, upsert), `action` (a host function; it reads when its last word is a read word) or `upstream` (+ `tool`: one of the package's new `upstreams`, the MCP server names the host provides), every string with `${input.<path>}` templates. `validatePackage` checks them against the format half of the eMCP contract (`exposeIssues` gives each issue its eMCP error code; `src/host/exposes.test.ts` replays packages/emcp `fixtures/exposes.json`): names, limits, one run, templates naming declared inputs, the package's own kinds and upstreams, destructive names never exposed, a read binding never writing. Format version stays 2 (both keys are optional). `host-router.json` gains `acme.exposes`, `acme.badexposes` and `acme.exposeslist`; the Rust core mirrors it (`host/exposes.rs`, the contract constants).

NEW, all optional, so every version-1 package stays valid: the neutral records source `records:<kind>?query` and the write functions `records.upsert` / `records.delete` over a host-provided store (`RecordStore`, `MemoryRecordStore`, `recordsHost`, `parseRecordsSource`, `recordsValue`; a binding to an undeclared kind is an install issue); `tools: {<id>: {kind: mcp | script, title, url | command, args?, env?}}` with the consent card a host must show (`validateTools`, `toolConsent`, `toolConsentKey`, `toolCall`); `extensions: [{id, version, components?}]` checked against the host's registered extensions (`ExtensionDef.version`, `availableExtensions`, `versionSatisfies`, the third `validatePackage` parameter, `HostRouterOptions.extensions`); the package FILE's `author` + `signature` (Ed25519 over a context line + RFC 8785 canonical JSON: `canonicalJson`, `packageFileSignedBytes`, `signPackageFile`, `verifyPackageFile`, WebCrypto). New fixture `fixtures/host-package.json` (signed with the RFC 8032 §7.1 TEST 1 key); `host-router.json` gains five packages and a flow. The Rust core mirrors validation, tools, `parse_records_source`, canonical JSON and the signed bytes.
- Allocation exception (NEW-77): the core's cold-start allocation count on mint 200,085 → 201,071 (+986: the kitchen sink's VoiceWave and its mark, and the `voiceWave` style constants) and the cold-start node count +2 for every renderer (the same two nodes); deterministic, measured twice.

- Allocation exception (VAPP-122): the core's cold-start allocation count on the Mint runner 200,069 → 200,085 (+16: the catalog's new `bind` function entry, 14 for its signature + 2 for its name and map key); `budgets.json` records exactly 200,085.
- VAPP-122: app RECORDS. A package may declare `records: {<kind>: {schema, title?, description?}}`, a JSON Schema SUBSET per kind (string | number | integer | boolean | array; enum, items, maxLength, minimum, maximum, format date | date-time | time; required; additionalProperties); `validatePackage` checks every kind (a kind's name `^[a-z][a-z0-9_]{0,31}$`, the reserved row keys id, createdAt, updatedAt, createdBy, author refused), `validateRecordSchema(schema, at)` and `validateRecord(schema, data)` are the two validators every host runs (the TS reference, the Rust core; `fixtures/host-router.json` `records` + the `acme.hours` / `acme.badrecords` packages replay them). The host keeps the rows (Exponential: one synced table, the `exp:records` source).
- VAPP-122: the `bind` ACTION, the catalog's 33rd built-in (`{functionCall: {call: "bind", args: {path, source, params?}}}`): re-follows a data model path from a source with `params` appended as its query (`sourceWithParams`: keys sorted, percent-encoded, null skipped, objects as JSON; `fixtures/host-policy.json` `sourceParams`), through the router like a server's bindDataModel (the package's `sources` allowlist applies), and the host cancels its earlier subscription at that path (subscriptions are keyed by path now). The prompt's functions line gains its signature; three rule sentences lost a word each so `budgetTokens` stays 7335.
- EXP-1385: a pointer write that lands always reads back. `-` still appends on a write and now reads an array's LAST element (the one the append landed on), so `readPointer(writePointer(data, "-", v).data, "-")` is `v` in every core (it read nothing, which the nightly `pointer` fuzz target caught on two nights). The Rust core's `get_pointer` reads digit-only indices like the TS core (`/+1` no longer reads item 1). New fixture `fixtures/pointer.json` (both fuzz units + the append, remove and refusal cases) and conformance suite `pointer`, replayed by the Rust core, gpui, the web renderers, SwiftUI and Compose. The web `getPointer` is the core's `readPointer`, and the React renderer's live reader follows a `-` binding too (a node bound to `/log/-` repaints on an append).
