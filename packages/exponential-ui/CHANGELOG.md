# Changelog: `@exponential-at/ui`

All notable changes to this package. The SDK packages share one version and
release together from a `ui-v<version>` tag (`packages/exponential-ui/release/README.md`).

## 0.1.0 (2026-10-23)

First release.

- Budget exception (VAPP-128): `@exponential-at/ui/conformance` gzip 177,065 → 177,137 (+72, measured: the regenerated macro, geometry and baseline fixtures the entry bundles under the new Stack/Section/overlay defaults); bytes stay within budget.
- VAPP-128: defaults where agents kept repeating a mistake: an unset `Stack.align` centres a horizontal row (a column still stretches; per breakpoint for a responsive direction), a Section keeps `$spacing.sm` under its band (was `xs`), the Devices template puts its List inside the Section (count bound to `/devices/count`), and the prompt asks for List + Row instead of Markdown bullets and ONE default Button per screen. `eval:parity` survives the removed template view and measures the Section band on its specimen shots; `eval:record` sends the described prompt (it sent `Section: undefined` for all 75 components, which VAPP-127's CLI recordings were made with). The corpus is re-recorded through the Claude CLI on the final prompt, and the same recorder's run on VAPP-125's prompt is committed beside it (`eval/baseline-1181/`, `bun eval/score.ts --fixtures eval/baseline-1181`), both scored with today's rubric: validator-clean 10/30 → 15/30, issues 43 → 24, components 469 → 385 (max 50 → 29), Stack 121 → 57, primary-action 9 → 10 of 14. The gain is VAPP-126's macros and VAPP-128's defaults and prompt together. The CLI wrote the machine owner's name, address and org into some sample data; it is redacted to Alex / example.com / acme in both recordings. An overlay's wrapper now follows its row's alignment (core + web), so a Menu or Dialog button lines up in a centred or Toolbar row.
- Budget exception (VAPP-126, the merge train's named exception: a new component grows a budget by exactly what it adds): the catalog prompt `budgetTokens` 7000 → 7349 (the six layout macros' own blocks, 1,278 chars, + the layout rule that names them, 118 chars: +1,396 chars / +349 tokens, the measured total, no slack); npm `@exponential-at/ui/prompt` 129,024 → 135,823 B (+6,799), `@exponential-at/ui/schema` 169,984 → 176,665 B (+6,681), `@exponential-at/ui/conformance` 1,944,225 → 2,057,625 B, gzip 172,032 → 177,065 (+113,400 / +4,985 over master's measured 172,080, which already sat 48 B over its budget after VAPP-152: the macros' catalog entries, schema, fixtures and kitchen-sink cases). Every other entry stays within its budget unchanged.
- VAPP-126: six layout macros the ergonomics corpus kept rebuilding by hand: `Page` (an AppBar row over a padded scrolling body), `Toolbar` (controls in one bottom-aligned row that wraps, a `trailing` action), `SplitView` (list + detail, one column at a time on phones with a back button that writes the bound `open`), `FieldGroup` (fields side by side, stacked on phones), `FormActions` (children, Cancel, then THE submit) and `StatTile` (label, value, toned change, sparkline). They expand from existing parts (AppBar, Card, Button, Separator, Sparkline), so every renderer paints them with no new painter code; the prompt grows by 1,396 chars (budget 7000 → 7349 tokens). Review (#1187): a `display: none` box (a SplitView's phone back bar) reaches SwiftUI and Compose as invisible, so nothing of its zero-framed subtree paints, takes taps or stays in the a11y tree (SwiftUI drew the back button's glyph past the zero frame); gpui, which clips it, leaves the subtree out of the Tab order as the web does.
- VAPP-152: `compileNodeSheet` keeps each styled node's rules (`NodeSheet.chunks`, cached per node object), and the new `nodeSheetBatches` splits the node sheet into `<style>` batches. A streamed `updateComponents` appends one batch with its new nodes' rules; the batches whose rules are unchanged keep their element, so Chromium no longer re-matches every node of the surface. `share` (structural sharing between two reduced trees, React's VAPP-141 helper) moved to `@exponential-at/ui/web`. The reducer and the macro expander read one shared catalog view (`sharedCatalogView`) instead of copying every table on each update.
- Budget exception (VAPP-125, the merge train's named exception): `@exponential-at/ui/conformance` 1,888,256 → 1,944,225 B (+55,969: the bound fixture cases of the 18 newly bindable props the entry bundles; gzip 171,938 stays within its 172,032 budget). No renderer entry moved past its budget.
- VAPP-125: the data-shaped props take a binding or a call: `Section.count` / `caption` / `loading`, `Image.alt`, `Row.icon` / `selected` / `chevron`, `Chip.tone`, `Icon.name` / `tone`, `Button.icon`, `Slider.min` / `max`, `Badge.variant`, `CodeBlock.variant`, `Stack.direction` / `align` / `justify`. Literal props expand and paint exactly as before. The ergonomics eval: on the corpus Opus 5.5 recorded through the CLI (VAPP-127) 42 → 39 validator issues (13/30 clean either way: the rest are icon names outside icons.json, `emptyText` on List, style keys outside the whitelist); on the earlier session recordings 18/30 → 29/30 clean. `Breadcrumb.items` stays a literal list: the macro lays its items out at expand time (like `Meter.segments` and `Stepper.steps`), a bound list would paint an empty nav.
- VAPP-147: `nativeRecipeProps` and `validateProps` read the catalog view and the part table built once per extension list (they rebuilt both on every call, i.e. every painted node on every render).
- VAPP-146: `fixtures/interactions-round1.json` `select`: an empty-string option value is an ordinary value on every renderer.

- `@exponential-at/ui/web/primitives` (FEED-131): the primitives' class recipes, framework-free and shared by the React and Solid primitive sets (cva recipes under their shadcn names, plain strings as `<MODULE>_CLASSES`, `cn`). New runtime dependencies: `class-variance-authority`, `clsx`, `tailwind-merge`.
- The web-parity check covers the primitive specimens (`fixtures/primitive-specimens.json`, group `primitive`), compared over the whole page body.
- `fixtures/toast-stack.json`: the toast stack contract both toast primitives follow.

- The core catalog (components with props, events and model-facing descriptions), the macro table, the A2UI basic catalog mapped onto it, the style whitelist and the token names.
- The runtime theme format, three built-in themes and the theme builder.
- Codegen of the catalog constants for TypeScript, Swift, Kotlin and Rust.
- The host API shared by every renderer: transports, functions, bindings, negotiation, URL policy and declarative packages.
- The agent prompt and the validator. VAPP-108: the prompt is sectioned (`sections`, `only`, `componentPrompt(name)`, `catalogIndex()`: rules + a one-line index first, a component's block on demand), the typed authoring DSL (`defineSurface`, `ui.<Component>()`, `bind` / `call` / `event` / `run`, `ComponentProps` generated from the catalog) and the ergonomics eval under `eval/` (the corpus, the cached replies, the scorer, the web render, the Devices parity on web and desktop, the rewrite gap list).
- The fixtures every renderer replays, plus the conformance suite and `conformance:check`.
- VAPP-106 (after FEED-128/130/131): the size gate covers `@exponential-at/ui-solid` (`.`, `./primitives`, `./styles.css`), `@exponential-at/ui-element` (`.`, `./define`, `dist/standalone.js`) and the shared web layer (`./web`, `./web/primitives`), and fails a renderer entry that bundles the described catalog, the prompt, the schema emitters or a fixture; the toast constants are written in `web/primitives/toast.ts` (held equal to `fixtures/toast-stack.json` by its test) so the primitives' recipes ship no fixture.
- VAPP-106: a size budget. The root entry ships the runtime catalog without its descriptions and examples (`generated/core.runtime.json`; `describeCatalog()` attaches them), and the prompt, the schema emitters, the conformance suite and the host API are entries of their own (`@exponential-at/ui/prompt`, `./schema`, `./conformance`, `./host`): the root bundle went from 1.74 MB / 230 KB gzipped to a fraction of it (`release/sizes.json`); `release/size.ts` measures every npm entry, the xcframework, the Android libraries and the crate, and CI fails a change over `release/size-budget.json`.
- `Trace` + `TraceItem` (shadcn's Trace: icon, title, muted detail, a collapsible content rail; `status` running|error|pending, `size` default|sm), the Text `shimmer` (`textShimmer`, `fixtures/text-shimmer.json`), CodeBlock `variant` (destructive) + `size` (sm) in shadcn's code-block look, the `ansi` language and the `success`/`warning`/`error` token kinds (`codeText`, `ansiRuns`).
- `@exponential-at/ui/web`: the framework-free web renderer layer (theme and base CSS, node sheets, the bind pass, URL/media policy, host plugin types, the natives' pure helpers) and `globalsCss`, a theme as plain shadcn globals.
- `orange`, the brand-coloured reference theme: the exponential look with an orange primary.
- The real-font geometry matrix: the kitchen sink, the responsive section and a project dashboard, in every built-in theme, both modes, four widths and both directions.
